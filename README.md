# نظام إدارة سناتر الدروس الخصوصية | Educational Center ERP (Egypt)

> **نظام سحابي ومحلي متكامل لإدارة سناتر الدروس الخصوصية في مصر، مصمم خصيصاً باللغة العربية وبواجهة RTL للتعامل مع أوقات الذروة وازدحام بوابات الدخول، وإدارة الخزينة والعهد المالية، وتصفية حسابات المدرسين بدقة متناهية.**
>
> An ultra-fast, Arabic-first localized ERP system designed specifically for Egyptian tutoring centers ("السناتر"), eliminating paper records, speeding up door check-ins during rush hours, automating teacher financial splits, and isolating receptionist shift cash registers.

---

## 🌟 أبرز مميزات النظام | Key Features

### 1. واجهة عربية أصيلة بالكامل (Arabic-First & Native RTL)
- مصمم بالكامل باللغة العربية من اليمين إلى اليسار (RTL) متوافقاً مع ثقافة السناتر المصرية ومصطلحاتها اليومية (حصص، سنتر، مذكرات، بوفيه، تصفية حسابات).
- خط عربي فائق الوضوح (**Cairo Font**) مخصص للشاشات ومكاتب الاستقبال السريعة.
- محرك بحث صوتي وإملائي ذكي يتجاهل فروق الهمزات والتاء المربوطة (`أ / إ / آ -> ا` و `ة -> ه` و `ى -> ي` وإزالة التشكيل) للوصول لبيانات الطالب في أقل من 15 مللي ثانية.

### 2. تسجيل دخول فائق السرعة أثناء الذروة (Rush-Hour Lobby Check-In)
- واجهة لوحة تحكم حية تعرض الحصص النشطة حالياً والتي ستبدأ خلال 30 دقيقة.
- **تعدد مكاتب الاستقبال المتزامنة (Multi-Desk Concurrency):** إمكانية عمل أكثر من موظف استقبال في نفس الوقت (Desk 1, Desk 2) مع مزامنة لحظية فورية عبر WebSockets لمنع تكرار تسجيل أي طالب مرتين.
- تسجيل طالب جديد على البوابة في أقل من 10 ثوانٍ (Quick-Add).

### 3. دعم وسائل الدفع المصرية (3 Payment Channels)
- **الكاش (Cash):** إيداع فوري في درج المكتب المخصص.
- **فودافون كاش ومحافظ المحمول (Vodafone Cash):** تسجيل رقم المحول والمعاملة.
- **إنستاباي (InstaPay):** تسجيل رقم التحويل البنكي اللحظي.

### 4. مطابقة الأعداد مع مساعد المدرس (In-Hall Headcount Reconciliation)
- مطابقة فورية بين عدد الطلاب المسجلين بالاستقبال والعدد الفعلي الذي قام بحصره مساعد المدرس داخل القاعة لمنع تسلل طلاب بدون دفع الحصة.
- تسوية الفروق وتوثيق الملاحظات قبل تصفية الحصة.

### 5. التصفية المالية الآلية للمدرسين (Automated Session Settlements)
- تطبيق المعادلة المالية المعتمدة في مصر فوراً:
  $$\text{إجمالي إيراد الحصة} = \text{عدد الطلاب المتفق عليه} \times \text{سعر الحصة}$$
  $$\text{حق السنتر} = \text{عدد الطلاب} \times \text{نسبة السنتر الثابتة (مثلاً 25 ج.م)}$$
  $$\text{صافي مستحقات المدرس} = \text{إجمالي الإيراد} - \text{حق السنتر}$$
- طباعة إيصال تصفية حساب باللغة العربية وصرف النقدية من درج موظف الاستقبال مع توقيع المستلم.

### 6. عهدة ودرج كاش منفصل لكل موظف استقبال (Shift Cash Drawer Control)
- كل موظف استقبال يفتح ويغلق ورديته بدرج كاش مستقل ومحمي لمنع التداخل والخلط بين الموظفين.
- احتساب الكاش المتوقع لحظياً: $\text{الافتتاحي} + \text{الكاش المقبوض} - \text{مصروفات ومستحقات المدرسين} - \text{مصاريف البوفيه والتشغيل}$.
- جرد نهاية الوردية وحساب العجز أو الزيادة وتثبيت التقرير للمدير.

## 🏗️ البنية التقنية | Architecture Stack

| الطبقة | التقنية المعتمدة | الدور والهدف |
| :--- | :--- | :--- |
| **الواجهة الأمامية** | React 18 / Vite 5 / TypeScript | سرعة قصوى وتحديث سلس للواجهات |
| **التصميم والتعريب** | Tailwind CSS + RTL + Cairo Font | واجهة RTL احترافية ومريحة للعين |
| **إدارة اللغات** | `i18next` + `react-i18next` | واجهة عربية افتراضية مع مبدّل فوري للإنجليزية |
| **الخادم والـ API** | Node.js 20+ / Fastify 4 / TypeScript | أداء عالٍ ومعالجة الطلبات المتزامنة |
| **المزامنة اللحظية** | Socket.io (WebSockets) | مزامنة الحضور بين مكاتب الاستقبال فوراً |
| **قاعدة البيانات** | PostgreSQL 15+ (Docker) مع **Prisma ORM** | علاقات محكمة وقيود فريدة تمنع الدخول المزدوج |
| **الأمان والحماية** | Argon2id + JWT في كوكي HTTP-Only موقّعة + حدود مُعدّلات الطلبات + حارس CORS/CSRF | حماية بيانات الطلاب والمعاملات المالية |

## 🚀 خطة مراحل التنفيذ | Roadmap

1. **المرحلة الأولى (Phase 1): التخطيط والهندسة المعمارية (مكتملة)**  
   تحديد المتطلبات، تصميم الجداول، وتوصيف النظام بالكامل متضمناً النسخة العربية ودعم الـ RTL، واعتماد التقنينات: Fastify + PostgreSQL (Docker) + Prisma.
2. **المرحلة الثانية (Phase 2): التهيئة وبناء الواجهة العربية والربط الأساسي (مكتملة)**  
   إعداد مشروع React + Fastify، تهيئة خطوط Cairo ونظام الترجمة i18n، وشاشات تسجيل الدخول والاستقبال السريع والجداول الأساسية.
3. **المرحلة الثالثة (Phase 3): إدارة الحصص والتسويات المالية والخزينة (مكتملة)**  
   حسابات نسب السناتر وتصفية مستحقات المدرسين وإقفال ورديات مكاتب الاستقبال، مع تقارير اليوم وسجلات التدقيق.
4. **المرحلة الرابعة (Phase 4): الحماية والنشر عبر الإنترنت (قيد التنفيذ)**  
   تشديد الأمان (التحقق من الجلسات، CORS/CSRF، حدود معدلات الطلبات، سجلات الأخطاء الآمنة) واختبارات المصادقة وWebSocket ومخطط نشر Render/Supabase — تفاصيل حالة كل خطوة في [docs/progress.md](docs/progress.md).

## 🧪 حسابات الدخول التجريبية والتشغيل السريع | Demo Accounts & Quick Start

يستخدم النظام سكريبت تهيئة تلقائي عند كل إقلاع يزرع بيانات تجريبية كاملة وواقعية لسنتر دروس خصوصية شغال بالكامل (**سنتر الأوائل التعليمي**): قاعات وصالات، مدرسين، 40 طالباً، جدول حصص وجدول مواعيد (Timetable) لأيام متتالية، ورديات وحضور واستقبال، إيرادات يومية، تصفيات حسابات مدرسين، ومصروفات مع سجلات خزينة متطابقة — بحيث يستطيع مالك السنتر تجربة النظام وفهمه تماماً كأنها بيانات حقيقية. كما يزرع طبقة منصة SaaS كاملة: سنترات تجريبية إضافية وإدارة اشتراكات وإيراد شهري متكرر (MRR) - ويمكن تصفير بيانات أي سنتر بالكامل من لوحة المدير عند الرغبة في البدء من الصفر.

### 🔑 بيانات تسجيل الدخول (Demo Credentials)

| الدور (Role) | اسم المستخدم (Username) | كلمة المرور (Password) | الصلاحيات |
| :--- | :--- | :--- | :--- |
| **مدير السنتر (Admin)** | `admin` | `Admin@12345!` | صلاحيات كاملة: التقارير، التحليلات، المدرسين، القاعات، التسويات المالية، وإعدادات السنتر |
| **الاستقبال (Receptionist)** | `reception1` | `Desk@12345!` | تسجيل دخول الطلاب السريع، فتح/إغلاق وردية الخزينة، تسجيل المصروفات وحضور الحصص |
| **مدير المنصة (Super Admin)** | `superadmin` | `Platform@12345!` | لوحة تحكم إدارة المنصة: السنترات (Tenants)، الاشتراكات، الإيراد الشهري المتكرر (MRR)، ومراجعة بيانات كل سنتر |

### ⚡ خطوات تشغيل النسخة التجريبية محلياً (Run Demo Locally)

```bash
# 1. تشغيل قاعدة بيانات PostgreSQL عبر Docker
npm run docker:up

# 2. تطبيق ترحيلات قاعدة البيانات وزرع البيانات التجريبية
npm run db:migrate
npm run db:seed

# 3. تشغيل الخادم والواجهة
npm run dev:server   # يعمل على http://localhost:3000
npm run dev          # يعمل على http://localhost:5173
```
